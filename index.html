Liar's Dice with sealed hands.

A multiplayer bluffing game where dice rolls live as encrypted onchain state, bids escalate in public, and the contract reveals only whether the final call was true or false.

Why this exists

Normal onchain games leak the table.

Most blockchain games either reveal state too early or move the real game offchain. Liar's Dice needs hidden hands, public social pressure, and a final aggregate truth check. That is exactly the privacy shape CoFHE is meant to show.

privacy thesis

The table can settle a lie without learning the dice.

The contract only needs an aggregate predicate: count dice matching the challenged face plus wild ones, compare to the bid quantity, then reveal the boolean verdict. Individual dice are not public game data until elimination.

Gameplay loop

Public bluffing over private state.

Each turn creates tension because every bid is visible, every hand is sealed, and the only public truth arrives when someone challenges.

01

Join casual table

Two or more players join a room with fixed casual settings: five dice per player, ones are wild, no wager logic, and no turn timers for the first build.

02

Generate encrypted rolls

Use CoFHE encrypted randomness on the contract path. Each roll maps into a sealed die face, then the UI decrypts only the local player's hand permission.

03

Escalate bids

A bid is public: quantity plus face. Ones count as wild for any challenged face, so bluffing has the classic Liar's Dice pressure.

04

Call the bluff

The contract computes encrypted matches across all sealed hands, including wild ones, and decrypts only the comparison result: bid good or bid was a lie.

05

Eliminate and reveal

For casual MVP, the losing player is eliminated by the table rule we implement first. Once elimination happens, all hands can reveal for clarity, replay, and end-of-round trust.

Modes

Casual mode is the build target.

We are intentionally avoiding wager logic, timers, penalties, and tournaments until the core privacy game feels good.

players

2+ seats

Start with casual rooms for two or more players. Keep joining, seating, bidding, and challenge resolution obvious.

rule

Ones are wild

A die showing one counts toward the challenged face. The encrypted match predicate checks face equality or wild one.

feel

Cup-first 3D

The primary interaction should feel like shaking a physical cup, planting it upside down, and privately peeking under it.

Stack

Built like a privacy game, not a normal casino app.

The technical stack should make encrypted state the centerpiece while keeping the first demo practical and deployable.

ContractsSolidity, Foundry, `@fhenixprotocol/cofhe-contracts/FHE.sol`, encrypted integer and boolean operations for dice counts and verdict checks.
NetworkArbitrum Sepolia for all contracts, room actions, challenge settlement, and event indexing.
Game engineThree.js for the 3D table, cup, dice, camera, and lighting; Rapier 3D for cup shake and dice tumble physics; GSAP for UI transitions outside the canvas.
FrontendVite React or Next.js, wagmi/viem, RainbowKit or ConnectKit, `@cofhe/sdk` and `@cofhe/react` for encrypted inputs and permitted decryptions.
State and indexOnchain events for canonical room history; lightweight offchain indexer for lobby discovery and replay-friendly bid history. No timer system in the casual MVP.
RandomnessUse Fhenix CoFHE encrypted randomness, such as `FHE.randomEuint8()`, then map into die faces while keeping raw rolls sealed.
AssetsImage-gen concept art for art direction, then production-ready 3D assets: dice meshes, cup mesh, felt table material, sealed opponent silhouettes, and encrypted glow shaders.
TestingFoundry unit tests for wild-one matching and verdict resolution, deterministic game-engine smoke tests, browser screenshots, and manual table-play verification with multiple wallets.
Architecture

Only the predicate becomes public.

The system keeps plaintext dice out of the public path. Public chain state is useful for coordination and settlement; CoFHE handles encrypted computation.

browser

Player wallet and 3D client

Signs table actions, runs the Three.js cup/dice scene, displays own private hand when permitted, and never receives other players' plaintext rolls before elimination.

arbitrum sepolia

GameTable contract

Stores room state, turn order, public bids, encrypted hand handles, challenge requests, and resolution events.

cofhe

Encrypted computation

Generates sealed dice, counts challenged-face matches plus wild ones, and compares the encrypted total against the public bid quantity.

threshold decrypt

Verdict and elimination reveal

During play, only the boolean challenge verdict is revealed. After elimination, all hands can reveal for a clean casual-game resolution.

indexer

Lobby and replay layer

Reads public events for room lists, bid timelines, player status, and demo replays without indexing secret dice values.

Finalize next

The important choices are now locked.

The remaining work is implementation detail, not product ambiguity: build the casual privacy loop first, then expand later.

rules

Ones are wild

The bid check counts dice equal to the challenged face plus dice showing one. This is locked for the casual MVP.

entropy

CoFHE random rolls

Use encrypted random values from Fhenix, keep roll handles sealed, and decrypt only the local hand plus final elimination reveal.

reveals

All hands after elimination

Hands remain sealed during active play. Once elimination resolves, reveal all hands so the table gets a satisfying end-state.

scope

No timers or penalties yet

Casual mode should feel smooth before we add ranked pressure, wagers, slashing, or tournament constraints.

Build path

Start with one casual 3D table on Arbitrum Sepolia.

Recommended MVP: two or more players, five dice each, ones as wild faces, physical cup-shake interaction, public bid ladder, encrypted aggregate resolution, and all-hand reveal after elimination.
